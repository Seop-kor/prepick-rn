# 더보기 화면 로그아웃 API 연결과 내 이름 표시

## Problem Statement

더보기 화면의 로그아웃 버튼은 확인 모달만 닫을 뿐 실제로 로그아웃하지 않는다. 고객은 기기에서 로그아웃할 방법이 없고, 서버에는 기기의 refresh token 세션이 그대로 남는다. 또 더보기 화면에는 앱 버전 외에 어떤 계정으로 로그인했는지 알려주는 정보가 없다.

## Solution

로그아웃 확인 모달에서 로그아웃을 누르면 서버 `logout(refreshToken)` 뮤테이션으로 세션 폐기를 요청하고, 응답을 기다리지 않고 곧바로 기기의 토큰·장바구니·서버 데이터 캐시를 비운다. 로그인 가드가 바뀌면서 고객은 즉시 웰컴 화면으로 이동한다. 서버 요청이 실패해도 고객에게 알리지 않는다.

더보기 제목 아래에 프로필 영역을 두고 로그인한 고객의 이름을 `홍길동님` 형식으로 보여준다. 이미 로그인된 상태로 앱을 열면 스플래시가 떠 있는 동안 이름을 미리 받아오므로, 더보기에서 이름을 기다리는 일이 거의 없다. 그래도 이름을 아직 받지 못했으면 스켈레톤을 보여주고, 조회에 실패하면 프로필 영역만 숨긴다. 앱 버전과 로그아웃은 항상 보인다.

## User Stories

1. 고객으로서 더보기 화면에서 로그아웃하고 싶다. 그래야 다른 사람이 내 계정으로 주문하지 못하게 할 수 있다.
2. 고객으로서 로그아웃 전에 확인 모달을 보고 싶다. 그래야 실수로 로그아웃하지 않는다.
3. 고객으로서 확인 모달에서 취소를 누르면 로그인 상태가 유지되길 원한다. 그래야 마음이 바뀌어도 아무 일도 일어나지 않는다.
4. 고객으로서 로그아웃을 누르면 기다림 없이 바로 웰컴 화면으로 이동하고 싶다. 그래야 로그아웃이 끝났음을 바로 알 수 있다.
5. 고객으로서 네트워크가 불안정해도 로그아웃이 되길 원한다. 그래야 오프라인이나 서버 장애 중에도 기기에서 계정을 정리할 수 있다.
6. 고객으로서 서버 로그아웃 실패 같은 내부 문제로 오류 알림을 보고 싶지 않다. 그래야 이미 끝난 로그아웃을 두고 혼란스럽지 않다.
7. 고객으로서 로그아웃하면 서버에서도 내 기기 세션이 폐기되길 원한다. 그래야 기기에 남은 refresh token이 다시 쓰이지 않는다.
8. 고객으로서 로그아웃하면 장바구니가 비워지길 원한다. 그래야 다음에 로그인한 사람이 내 장바구니를 보지 않는다.
9. 고객으로서 로그아웃하면 내 주문내역·이름 같은 서버 데이터가 기기에서 사라지길 원한다. 그래야 다른 계정으로 로그인했을 때 이전 계정 정보가 보이지 않는다.
10. 고객으로서 더보기 화면에서 내 이름을 보고 싶다. 그래야 어떤 계정으로 로그인했는지 알 수 있다.
11. 고객으로서 이름을 불러오는 동안 자리 표시를 보고 싶다. 그래야 화면이 비어 보이거나 깜빡이지 않는다.
12. 고객으로서 이름 조회가 실패해도 앱 버전과 로그아웃은 계속 쓰고 싶다. 그래야 정보 조회 문제가 로그아웃을 막지 않는다.
13. 고객으로서 홈에서 이미 불러온 이름이 더보기에서도 바로 보이길 원한다. 그래야 같은 정보를 다시 기다리지 않는다.
14. 개발자로서 refresh token 거부로 인한 자동 로그아웃은 지금처럼 기기 정리만 하길 원한다. 그래야 이미 거부된 토큰으로 불필요한 서버 요청을 보내지 않는다.
15. 개발자로서 로그아웃 흐름을 Jest와 Maestro로 검증하고 싶다. 그래야 이후 변경에서 로그아웃 회귀를 잡을 수 있다.
16. 고객으로서 로그인된 상태로 앱을 열었을 때 홈이 뜨기 전에 더보기로 가도 이름이 바로 보이길 원한다. 그래야 스켈레톤을 보지 않는다.
17. 고객으로서 앱을 열 때 이름 조회가 실패해도 앱이 평소처럼 열리길 원한다. 그래야 이름 조회 문제가 앱 진입을 막지 않는다.
18. 고객으로서 로그아웃 상태로 앱을 열면 이름 조회 없이 바로 웰컴 화면을 보고 싶다. 그래야 불필요하게 기다리지 않는다.

## Implementation Decisions

### Modules

- GraphQL mutations
- API
- TanStack hooks
- TanStack query client
- IndexScreen
- MoreScreen
- Maestro 로그아웃 시나리오

### 서버 로그아웃 요청

- 서버 `logout(refreshToken: String!): Boolean!`은 `@Public()`이고 멱등이다. 알 수 없거나 형식이 잘못된 토큰에도 true를 반환한다.
- GraphQL mutations에 `logout` 문서를 추가한다.
- API에 refresh token을 받아 `logout` 뮤테이션을 요청하는 메서드를 추가한다. 다른 인증 전 API처럼 `skipAuth`로 보낸다. 그래서 access token 갱신을 거치지 않고, 토큰을 지운 뒤에도 요청이 독립적으로 진행된다.

### 로그아웃 동작

- 로그인과 같은 형태로 TanStack hooks에 `useLogout` 뮤테이션 훅을 추가한다.
- `useLogout`의 실행 순서:
  1. 기기 토큰을 지우기 전에 현재 refresh token 값을 읽는다.
  2. refresh token이 있으면 서버 로그아웃 요청을 시작하되 기다리지 않는다. 요청 실패는 삼키고 알리지 않는다.
  3. 기존 로컬 `logout()`(토큰 삭제, 장바구니 비우기, query cache 비우기)을 기다린다.
- 로컬 `logout()`은 바꾸지 않는다. refresh token 거부 시 자동 로그아웃 경로는 계속 로컬 정리만 한다. 이렇게 하면 session과 HTTP client 사이에 순환 import도 생기지 않는다.
- 화면 이동은 별도로 하지 않는다. 토큰이 사라지면 루트 레이아웃의 로그인 가드가 바뀌어 웰컴 화면으로 이동한다.

### 더보기 화면

- 로그아웃 확인 모달의 로그아웃 버튼은 모달을 닫고 `useLogout`을 실행한다. 서버 응답을 기다리지 않으므로 버튼 로딩 표시는 쓰지 않는다.
- 취소는 지금처럼 모달만 닫는다.
- 더보기 제목 아래에 프로필 영역을 추가한다. 홈과 같은 `useCurrentUser` 쿼리를 쓰므로 홈에서 받은 캐시를 그대로 사용한다. currentUser 쿼리의 필드는 바꾸지 않는다(이름만 사용).
- 프로필 영역 상태:
  - 조회 중: 기존 SkeletonBlock으로 이름 자리를 표시한다.
  - 성공: `{이름}님`을 크게 표시한다.
  - 실패: 프로필 영역을 렌더링하지 않는다. 별도 오류 UI나 재시도는 없다.
- 앱 버전 행과 로그아웃 행은 프로필 상태와 상관없이 항상 표시한다.

### 앱 진입 시 currentUser 프리페치

- IndexScreen은 `hydrateAuth()`가 끝난 뒤 로그인 상태(access token 있음)이면 currentUser를 query client로 프리페치하고, 프리페치가 끝난 뒤 스플래시를 숨긴다. 로그아웃 상태면 프리페치 없이 바로 스플래시를 숨긴다.
- 프리페치는 성공·실패와 상관없이 끝나면 스플래시를 숨긴다. 실패해도 오류를 알리지 않고 지금처럼 홈으로 이동하며, 홈의 `useCurrentUser`가 마운트될 때 다시 요청한다.
- 별도 시간 제한은 두지 않는다. 재시도 없이 요청 한 번이 끝날 때까지 기다린다(HTTP 타임아웃 15초, 토큰 갱신이 끼면 그만큼 더).
- 프리페치와 `useCurrentUser`는 같은 쿼리 정의(쿼리 키 `['currentUser']`와 조회 함수)를 공유한다. 쿼리 키를 두 곳에 따로 적지 않는다.
- 프리페치 중 refresh token이 거부되면 기존 자동 로그아웃 경로가 기기를 정리하고, 로그인 가드가 바뀌어 웰컴 화면으로 이동한다.
- 콜드 스타트에만 적용한다. 로그인 직후에는 프리페치하지 않는다. 토큰 저장 즉시 홈이 마운트되어 스스로 요청하므로 별도 프리페치의 이득이 없고, 로그인 로딩을 늘려 흐름을 바꾸지 않는다.

### 쿼리 재시도 정책

- query client의 쿼리 기본 옵션을 `retry: false`로 바꾼다. 앱 전체 쿼리가 실패 시 재시도하지 않고 바로 오류 상태가 된다. 뮤테이션은 원래 재시도하지 않으므로 그대로 둔다.

## Testing Decisions

- 외부에서 보이는 동작만 테스트한다. 내부 상태나 호출 순서 구현 세부보다 결과(무엇이 화면에 보이는지, 어떤 요청이 나가는지, 로컬 정리가 끝났는지)를 확인한다.
- MoreScreen 렌더 테스트: 훅을 mock하고 기존 home·orders 화면 테스트처럼 react-test-renderer를 쓴다.
  - 이름 조회에 성공하면 `{이름}님`을 표시한다.
  - 조회 중이면 스켈레톤을 표시한다.
  - 조회에 실패하면 프로필 영역을 숨기고 앱 버전과 로그아웃은 표시한다.
  - 확인 모달에서 로그아웃하면 로그아웃을 실행하고, 취소하면 실행하지 않는다.
- `useLogout` 동작 테스트: 기존 hooks 테스트처럼 `useMutation`을 mock해 mutationFn을 꺼내 검증한다.
  - 로그아웃하면 지우기 전의 refresh token으로 서버 로그아웃을 요청하고 로컬 로그아웃을 실행한다.
  - 서버 응답이 끝나지 않아도 로컬 로그아웃이 끝난다.
  - 서버 요청이 실패해도 로그아웃은 오류 없이 끝난다.
  - refresh token이 없으면 서버 요청 없이 로컬 로그아웃만 한다.
- API 테스트: 기존 API 테스트처럼 `requestGraphQL`을 mock한다. 로그아웃하면 refresh token과 `skipAuth`로 `logout` 뮤테이션을 요청한다.
- 기존 session 테스트(로컬 `logout()`이 토큰·장바구니·캐시를 비움)는 그대로 유지한다.
- IndexScreen 렌더 테스트(새 파일): `hydrateAuth`·API·SplashScreen을 mock하고 react-test-renderer로 렌더링한다.
  - 로그인 상태로 진입하면 currentUser를 받아온 뒤 스플래시를 숨기고, 받은 이름이 `['currentUser']` 캐시에 들어 있다.
  - currentUser 응답이 끝나기 전에는 스플래시를 숨기지 않는다.
  - currentUser 조회가 실패해도 스플래시를 숨긴다.
  - 로그아웃 상태로 진입하면 currentUser를 요청하지 않고 스플래시를 숨긴다.
- Maestro: 기존 launch-and-login subflow로 로그인한 뒤 더보기 → 로그아웃 → 확인 모달의 로그아웃을 누르고 웰컴 화면(`휴대폰 번호로 로그인`)이 보이는지 확인한다. 더보기에 `{이름}님`이 보이는지도 확인한다.

## Acceptance Criteria

- [ ] AC-1: 더보기 화면에서 로그아웃 → 확인 모달의 로그아웃을 누르면 웰컴 화면으로 이동한다.
- [ ] AC-2: 확인 모달에서 취소를 누르면 모달만 닫히고 로그인 상태가 유지된다.
- [ ] AC-3: 로그아웃하면 기기에 저장된 토큰 삭제 전의 refresh token으로 서버 `logout` 뮤테이션을 `skipAuth`로 요청한다.
- [ ] AC-4: 로그아웃은 서버 응답을 기다리지 않고 토큰·장바구니·query cache를 비운다.
- [ ] AC-5: 서버 로그아웃 요청이 실패해도 로그아웃이 완료되고 오류 알림을 보여주지 않는다.
- [ ] AC-6: refresh token 거부로 인한 자동 로그아웃은 서버 로그아웃 요청을 보내지 않는다.
- [ ] AC-7: 더보기 제목 아래에 로그인한 고객의 이름을 `{이름}님` 형식으로 표시한다.
- [ ] AC-8: 이름을 불러오는 동안 프로필 영역에 스켈레톤을 표시한다.
- [ ] AC-9: 이름 조회에 실패하면 프로필 영역을 숨기고 앱 버전과 로그아웃은 계속 표시한다.
- [ ] AC-10: Maestro 로그아웃 시나리오가 로그인 → 더보기 이름 확인 → 로그아웃 → 웰컴 화면 확인까지 통과한다.
- [ ] AC-11: 로그인 상태로 앱을 열면 스플래시가 떠 있는 동안 currentUser를 받아오고, 받은 뒤 스플래시를 숨긴다. 이 경우 더보기에 처음 들어가도 이름 스켈레톤이 보이지 않는다.
- [ ] AC-12: 앱 진입 시 currentUser 조회가 실패해도 스플래시를 숨기고 홈으로 이동하며 오류 알림을 보여주지 않는다.
- [ ] AC-13: 로그아웃 상태로 앱을 열면 currentUser를 요청하지 않는다.
- [ ] AC-14: 쿼리는 실패해도 재시도하지 않는다.

## Out of Scope

- 전화번호 등 이름 외의 계정 정보 표시와 currentUser 쿼리 필드 변경
- 프로필 편집, 회원 탈퇴, 알림 설정, 약관·고객센터 등 더보기의 다른 메뉴
- 서버 로그아웃 실패 시 재시도나 실패 알림
- 로그아웃 중 버튼 로딩 표시
- 모든 기기에서 로그아웃
- 서버 API 변경
- 로그인 직후 currentUser 프리페치(로그인 로딩에 이름 조회 포함)
- 스플래시 프리페치의 별도 시간 제한

## Further Notes

- 서버 요청을 기다리지 않으므로 앱이 바로 종료되면 서버 세션이 남을 수 있다. 남은 세션은 refresh token 만료로 정리되고, 기기에는 토큰이 없으므로 다시 쓰일 수 없다.
- 로그아웃 후 화면이 사라져도 이미 시작한 서버 요청은 계속 진행된다. query cache를 비워도 진행 중인 HTTP 요청은 취소되지 않는다.
- 스플래시 프리페치는 네트워크가 느리면 앱 시작을 최대 HTTP 타임아웃(15초)만큼 늦춘다. 사용자가 시간 제한 없이 완료까지 기다리기로 결정했다.
- 쿼리 재시도를 전역으로 끄면 일시적인 네트워크 오류에도 홈·주문내역 등이 바로 오류 상태가 된다. 다시 들어가거나 화면의 재시도 동작으로 복구한다.
